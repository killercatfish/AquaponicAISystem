## 2. Tomorrow's plan — fix the light

**Goal:** working brightness control via dashboard

### Steps in order

**A. Inventory (5 min)**
Bring to bench: multimeter, magnification (loupe or phone macro), soldering iron, fresh solder, solder wick or pump for rework if needed.

**B. Stop the service so it releases /dev/ttyUSB0**
```bash
ssh aquapi 'sudo systemctl stop aquaponics'
```

**C. Visual inspection (10 min, daylight + magnification)**
Look at every solder joint on the perfboard PWM dimmer. Suspicious signs:
- Dull or grainy appearance (proper joint = shiny)
- Cracks or rings around the lead
- Lead not fully wetted by solder
- Solder ball instead of conical fillet

Priority joints in order:
1. **2N2222 transistor pins** (Emitter, Base, Collector) — most likely culprit
2. **1kΩ resistor leads**
3. **HLG dim wire connections** to the perfboard
4. **ESP32 GPIO output pin** going to the transistor base
5. **ESP32 USB connector** — known weak point on DevKit V1, can crack from cable strain

**D. Multimeter continuity check (15 min)**
Set multimeter to continuity mode. Test each joint while gently wiggling the adjacent component:
- Probe from one side of the joint to the next solder pad in the circuit
- Any joint that breaks continuity under wiggle = needs reflow
- Special: test transistor emitter → ESP32 GND continuity (ground path is often the silent failure)

**E. Reflow suspicious joints (15 min)**
- Iron well-tinned at appropriate temperature (~370°C for leaded, ~400°C for lead-free)
- Apply iron to joint, feed fresh solder until joint flows smooth
- Let cool without disturbing
- If multiple joints look bad, **consider rebuilding on fresh perfboard** — faster than chasing intermittent joints

**F. Test serial path (5 min)**
```bash
# Verify device file is character device
ssh aquapi 'ls -la /dev/ttyUSB*'
# Should show: crw-rw---- ... /dev/ttyUSB0
# If shows -rw-r--r-- (regular file), see GOTCHAS below

# Configure baud and send test
ssh aquapi 'sudo stty -F /dev/ttyUSB0 115200 raw -echo && sudo bash -c "echo SET:0 > /dev/ttyUSB0"'
# Light should go off or to minimum

ssh aquapi 'sudo bash -c "echo SET:100 > /dev/ttyUSB0"'
# Light should go full bright

ssh aquapi 'sudo bash -c "echo SET:50 > /dev/ttyUSB0"'
# Light should go to half
```

**G. If light responds — restart service**
```bash
ssh aquapi 'sudo systemctl start aquaponics'
```
Then test dashboard brightness slider at `http://100.117.109.76:8000`.

**H. If light still doesn't respond after reflow**
Read ESP32 boot banner:
1. On Mac terminal: `ssh aquapi 'sudo cat /dev/ttyUSB0'` — leave hanging
2. Walk to basement, press EN/RST button on ESP32
3. Watch terminal:
   - **Garbled bytes + readable firmware text** = ESP32 alive, problem still in dim circuit
   - **Garbled bytes only** = firmware needs reflash from `esp32/hlg_light_controller/`
   - **Nothing** = USB cable, ESP32 power, or dead board

## 4. Operational gotchas (lessons from May 12)

These should live in INVENTORY.md when it's written. Don't repeat the mistakes:

- **NEVER** `sudo bash -c "echo > /dev/tty*"` if device doesn't exist — creates a regular file at `/dev/tty*` that blocks future device node creation. **Always check `ls -la /dev/ttyUSB*` for the `c` prefix (character device) before writing.**
- Service holds `/dev/ttyUSB0` open — stop service for manual serial tests
- Always `stty -F /dev/ttyUSB0 115200 raw -echo` BEFORE any `echo` write — without it, bytes go out at default 9600 baud and ESP32 sees garbage
- USB renumbering: ESP32 may come back at `/dev/ttyUSB1` after disconnect/reconnect. Long-term fix: udev rule for stable `/dev/aqualight` symlink based on CP2102 vendor:product (`10c4:ea60`)
- Pi user IS in `dialout` group — should work without sudo for most serial ops once permissions sort out
- DLI IoT Relay II has ONE GPIO input that gangs all switched outlets — can't independently control multiple devices on it
- Atlas EZO Isolated Carrier Board is generic — accepts pH, EC, DO, etc. chips (same SKU for the carrier)
- Memory drift is real: brain captures should be verified periodically against reality. Today corrected "Mac repo path", "Surveyor DO probe", "light HTTP transport drift" — all were wrong in brain.
